# 先用一条真实问题，把工具用起来

公开版初始数据刻意设置了两条虚构说法：同一“演示培训课程”的总学时分别为96和112。这两条均待核实，仅用于演示冲突提示，不对应任何机构真实课程；可用底稿为空是预期行为。

## 先核对什么

换成自己的真实事项后，再向有权确认的负责人核对：

1. 96具体指总学时还是实操学时？112对应哪版课程和哪个报名批次？
2. 哪一份文件是当前有效的官方口径，是否有版本号或发布日？
3. 是否可以用于对外宣传、有效至何时、由谁确认？

把得到的文件或答复保存为你有权保存的材料。口头回复也要注明回复人和日期，不自动冒充盖章文件。没有确认就继续保留待核实。

## 两种可能的处理

- **两个数值确实竞争同一总学时口径**：保留正确版本并补齐来源、确认记录和有效期；把过时版本退役，在备注中写明依据。
- **96为实操、112为总量**：根据真实材料修改事项，让“实操学时”和“总学时”各自对应明确语义，并分别记录确认。不能只为了让红色提示消失而改范围或事项。

未过期、已记录确认、没有冲突的条目才会进入可用底稿。导出的底稿保留来源、确认人、日期及适用范围，仍需要在正式发布前人工审阅。

## 怎样判断它是否有用

在“决策复盘 → 试用与反馈”关联项目13，记录一次真实工作：

- 使用前：原先要打开多少份文件，谁来确认，实际耗时或遗漏是什么。
- 使用后：是否更容易找到口径；是否发现了以前漏掉的问题；实际耗时怎样。
- 反馈：使用者的具体意见，不把自己的软件测试写成同事评价。
- 下一步：继续一个真实场景、修改一个问题，或停在目前的小版本。

不要为了给软件证明价值而编造节省比例。一次失败或无改善的试用，同样能帮助决定是否继续。

## 保护原有积累

修改前可以先下载完整备份。系统也会在每次成功修改前保存旧版本。资料原件仍在原位置，本工具只保存索引和核验记录，不改原DOCX、PDF或图片。
