# 以后如何把项目卡交给 Codex

打开工作台的“40 项目库”，选一张卡，先读启动条件和停止条件，再复制完整Codex提示词。提示词会带入该项目自己的用户、问题、首版范围、输入输出、验收与边界，不只是一个项目名称。

## 继续本工作台

下面这段可以在以后交给Codex，并补充实际需求：

```text
请继续本目录的职业发展工作台。先读取README.md、docs/接口约定.md和docs/公开版核查记录.md，检查当前文件与实际数据状态。保留data与backups，不用seed覆盖我的记录。先说明这次准备解决的真实问题，再进行必要修改，并用临时数据完成相关测试。此前已通过的检查不能冒充本次修改后的验收。
我的新需求与实际反馈：
（在这里写清具体工作场景和遇到的问题）
```

## 开始库里的另一个方向

复制项目卡后补充三项事实即可：

- 现在谁会用、实际工作怎样进行。
- 能提供哪些有权使用的资料，有哪些仍然未知。
- 第一版用什么具体结果验收。

新项目默认先放独立目录，明确与本工作台哪些内容共用。只有事实和需求稳定后才整合，避免为了统一而把所有项目做成一个难维护的大系统。

## 不需要重复开发的部分

- 项目01的轻量成果记录、项目05的轻量决策记录、项目13的本地事实中心，已在本工作台提供可操作版本；可以扩展现有功能。
- 能策Pilot、动态技能路由器、云游地图等已有项目应先读各自说明并运行必要检查，不能直接按卡片重建覆盖。
- 项目卡的候选状态由你管理；“软件可操作”“本人掌握”“真实用户采用”“产生业务效果”是不同证据，不要自动连带升级。
